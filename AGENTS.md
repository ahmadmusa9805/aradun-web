## Authority and task discipline
- Follow Propose → Approve → Implement → Test → Review → Accept → Next task using the permanent workflow below. Read current authorization and status from PROGRESS.md and DECISIONS.md; record explicit approvals and never infer acceptance or authorization beyond their stated scope.
- Before every task, read AGENTS.md, applicable nested instructions, PROGRESS.md, DECISIONS.md and relevant approved sources. Inspect existing implementation, tests and Git status/diff; preserve unrelated work. Never modify approved source documents without explicit authorization.
- Canonical sources are docs/sources/: 01 governs business scope/prices/phases; 02 IDs/routes/navigation; 03 sections; 04 design/themes/motion; 05 data/backend; 06 structure; 07 roadmap/dependencies/acceptance; 08 execution/evidence; 09 content/assets; 10 QA; 11 deployment; 12 operations; 13 growth.
- Explicit owner amendments supersede only their subjects. Use current source versions; embedded historical hashes/statuses are provenance. Preserve named gates and proposed/conditional qualifications, including R11–R13 recommendations.
- Manage task discovery and requirements lookup without asking the owner to repeat documented information or repeating settled planning. Recommend one eligible M00–M14 task using source 07 dependencies and priorities; state its ID, prerequisites, approval gates, expected files, scope, exclusions and acceptance criteria before implementation.
- Once a task is approved, complete its implementation and applicable verification without repeated permission requests for routine authorized work. Resolve ordinary implementation choices yourself; seek owner decisions for genuine conflicts, unresolved gates, significant architecture/security changes, providers, costs, credentials, production operations or scope changes.
- Stop after the approved task for review and acceptance. If blocked, explain the blocker and recommend eligible alternative work without starting it automatically. Conditional features and Phase 2/3 work require explicit authorization.
