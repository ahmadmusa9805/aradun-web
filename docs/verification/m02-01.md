## Implemented behavior and acceptance

| M02-01 acceptance | Actual evidence | Result |
| --- | --- | --- |
| Rejected connection promises recover safely | Same unavailable target fails through an owned loopback proxy, then connects after target availability is restored; pending promise cleared; concurrent opening shares one promise; warm callers reuse the same connection; close is idempotent and refuses new connections | PASS |
| Failed multi-document writes abort | Application transaction helper commits two collection writes; deliberate failure after both writes leaves neither record; returns the committed callback result | PASS against native MongoDB 8.0.34 replica set |
| No external API call occurs inside transactions | Helper imports only Mongoose types, has no provider/network dependencies and no business callers; sequential callback contract explicitly forbids external effects. Server failpoint injects one transient insert failure; callback retries twice, one committed record/event each, test delivery double called once after commit and never on rollback | PASS for current helper/call sites; future business callbacks require the same review and durable-outbox behavior |

Connection owner is constructed once per Express process, never per request. Explicit dbName; no Mongoose buffering, auto-index or auto-create. Rejected candidates close and clear. A successfully opened connection retains its existing driver monitor/pool during later topology outages, rather than spawning replacement clients. Startup checks replica-set identity before listening, exits safely if unavailable/missing and never prints the URI/driver error. Shutdown drains HTTP then closes MongoDB with a ten-second process exit guard. No database is opened by builds or importing the app factory.

Config bounds: maxPoolSize default 5 (allowed 1-20), selection 5000ms (100-30000), queue 2000ms (100-10000); fixed minimum pool 0, maxConnecting 2, connect 3000ms, socket inactivity 10000ms, idle 60000ms. Real saturation test with pool size 1 blocks the first find, verifies the second fails with MongoWaitQueueTimeoutError, then proves subsequent recovery. Aggregate budget is documented in the environment contract: application pools up to processes * monitored servers * maxPoolSize, plus monitoring sockets. No production capacity/SLA is approved by these local bounds.

Transactions use Mongoose's supported transaction/session handling: primary/snapshot/majority and 5000ms commit/write-concern limits. Driver owns retry/ambiguous-commit handling. Its installed convenient API retains an approximately 120-second retry window; no false claim that timeoutMS enforces a whole-transaction deadline. Future queries/use cases must supply their own bounded work/deadlines and explicit session to every participating operation; no parallel operations or external effects in a retryable callback. Arbitrary callback side effects cannot be sandboxed by this helper; this remains an enforced code-review/design constraint.
