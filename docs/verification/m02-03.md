## Acceptance and implementation

| M02-03 acceptance | Verified behavior | Result |
| --- | --- | --- |
| Audit follows committed sensitive operations | Successful append requires an active caller-supplied transaction; real synthetic sensitive write/audit commit together; deliberate later exception rolls both back; success without session refused. | Normal app cannot rewrite history | Service exposes append/read only; schema immutability, re-save checks and query/document/bulk mutation middleware reject update/delete/replace; original record preserved. | Snapshots omit raw message/credential contents | No before/after/body snapshot accepted. AuditEvent uses auditEvents, schemaVersion 1 and createdAt; no updatedAt/revision/archive/version key. Implements eventKey, Actor, action, targetType/targetId, outcome, occurredAt, correlationId, changedFields, safeSummary, optional reasonCode/actorIpHash and retentionClass. No TTL. The service never accepts/populates actorIpHash because the hashing/retention policy is unselected. Source indexes: unique eventKey, targetType/targetId/occurredAt/_id, actor.staffUserId/occurredAt, correlationId, occurredAt/_id, plus MongoDB _id. Automatic startup index creation remains disabled; tests explicitly build indexes on owned data only.

Initial operation mappings are source examples publish/article, role-change/staffUser and stage-change/opportunity. Only corresponding status/publishedAt, roles and stage field names accepted. These are audit vocabulary, not implemented business features. Extend vocabulary alongside authorized owning features rather than accepting arbitrary labels/messages. Current service target IDs are ObjectId strings; schema retains the source maximum 180-character string contract, and stable source-key service mappings are feature-timed. Retention classes security/business-change/privacy-action do not select legal retention periods.

Every call invokes an explicit authorization callback. Append supplies operation/action/target to it; read then additionally enforces active Admin, target-filtered latest records, default 25/max100 and 2000ms query bound. Returned DTO excludes raw actor identity, IP hash and internal persistence fields. It is a bounded recent target-history query, not an audit browser/export or general history pagination API. Record existence/visibility and real current staff identity/session/MFA must be checked by the M03/owning-feature callback before endpoint exposure. No permissive default grants, HTTP route or viewer exists; tests use explicit synthetic principals and do not prove real authentication.

Sequential same-event retries return the prior receipt; changed payload with the same key conflicts. Unique DB index prevents duplicate records in races; a concurrent duplicate write can return safe dependency failure and requires controlled whole-command retry after rollback. No exactly-once external delivery or success-before-commit is claimed. Success receipt inside a transaction is provisional until the originating service's outer transaction commits. Failure/denial evidence belongs outside failed business transactions; no hidden independent DB transaction runs inside append.

Audit persistence failure emits fixed audit_write_failed/correlation/severity to a separate local logging callback and returns a safe unavailable error. Default logging uses stderr with fixed code, generated UUID and UTC occurrence time, excluding raw errors, stack, bodies, tokens, headers or provider payloads. Backend startup/listener failures now use these correlated logs. Rejected logging input produces a generic safe record; failed sink returns false without exposing the thrown exception. Local sink acceptance is not proof of delivered monitoring; routing and human receipt remain M01-04/M13/M14 gates. No external network logger/provider runs inside transactions.

Application immutability does not block a MongoDB administrator or raw collection API. Production runtime credentials must restrict auditEvents to insert/find, with separate reviewed index/retention/erasure authority before deployment. No production DB RBAC has been provisioned/tested. Privileged restore/erasure is not an ordinary model mutation and is not implemented. Normal feature code must use the service, never raw model/collection mutation. Incompatible existing AuditEvent model registration fails rather than masking a different schema.
