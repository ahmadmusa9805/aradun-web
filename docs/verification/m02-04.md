## Implemented behavior

- Strict RateLimitBucket with source fields, createdAt/schemaVersion and no business revision/archive fields. Unique scope/subjectHash/windowStart and expire-at-date expiresAt indexes; autoCreate/autoIndex false. No index applied to owner databases.
- Shared atomic conditional increments: intake 10 per 10-minute fixed window; catalog 120 per minute. At most three collision retries, then safe 503; rejected requests never grow counters indefinitely. Expiry/window decisions use server time independent of TTL deletion. Cleanup eligibility is window end plus one hour, not a physical erasure deadline.
- HMAC-SHA-256 versioned scope/normalized socket identity, no raw identity in stored buckets or public errors. IPv4-mapped/expanded IPv6 normalize consistently. Backend-only canonical base64url secret with at least 32 random bytes; no secret value generated/persisted. Trust proxy explicitly false; forwarding headers ignored for limiter identity. NAT and frontend SSR requests can share a budget.
- Bounded Mongo operations (2-second server command cap, with existing independent connection timeouts). Before first admission, read-only verification requires exact nonpartial visible unique and TTL indexes. Successful verification is cached per limiter instance; administrative index removal afterward requires operational monitoring/restart/review, not a claimed continuous guard. Failed checks can recover after an explicitly reviewed apply. No in-memory/unlimited fallback.
- Catalog middleware wired through normal Express startup when local development secret is configured. Missing binding, secret/store/index readiness results in no-store 503/Retry-After 5 rather than false availability. Root readiness and authenticated job endpoint contracts unchanged. Hosted runtime remains unavailable until its actual deployment policy is selected; local defaults are not silently production settings.
- Reusable public POST JSON boundary: exact trusted Origin, JSON object, uncompressed body up to 32 KiB; 403/400/413/415 safe correlated errors. No public intake route created. Isolated HTTP test route places admission before body parsing/domain work, preserving approved counting of invalid JSON/oversized attempts after trusted media/origin checks. Domain schema allowlists remain owned by future actual handlers.
- Useful 429 safe code/message/correlation and integer Retry-After to window boundary. No challenge service, credential/auth flow, PII drafts, fake success or automatic migration.
