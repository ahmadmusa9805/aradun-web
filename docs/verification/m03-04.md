## Implementation

`createStaffLifecycle` refuses nondevelopment targets and requires existing reviewed collections/indexes. Owned test databases additionally require the existing test ownership marker, loopback replica set and test runtime. It creates no indexes/collections automatically. Every nonbootstrap command rechecks a current fresh MFA Admin; mutations fence the actor inside the transaction and compare the target revision. The actor's revision can advance as that write fence; no accessVersion bump occurs merely from inspection/provisioning.

The fixed `identityLifecycleControl` record `_id=staff-access` serializes mutations and records bootstrap completion/staff ID/hashed approval reference. It contains no password, session, seed or recovery secret. It is a minimal technical control for the task's mandatory one-time/race guarantees, not a settings/role builder or recovery backdoor.

New credentials use the existing maintained-library password preparation outside retryable transactions, then commit credential and StaffUser together. Provisioning creates an invited mapping only; explicit activation verifies the immutable subject. No matching-email linkage or invitation email. Roles/status/revoke increment accessVersion and invalidate sessions/challenges/packs/pending enrollment. No default password/public provisioning mechanism. Source AuditEvent actions are extended only for these lifecycle operations, with existing immutable audit fields/indexes; role-change evidence includes accessVersion.

The additive index planner now fingerprints `missingCollection`, including namespaces needing only MongoDB's default index. Explicit reviewed apply can create those namespaces after existing global unique-index preflight. This is necessary for the control model without inventing an unused secondary index. No owner apply was performed, and existing backup/evidence/hosted-apply restrictions remain.

The CLI defaults to inert help and rejects extra arguments, missing arming, hosted/remote targets, wrong database confirmation and missing current session before changes. It uses `DB_OPERATIONS_URI`, never application URI fallback; secrets enter via bounded private stdin. Outputs are safe IDs/state/version/count/audit receipts, not names/email/passwords/session IDs. Approval-reference presence/matching is validation, not automatic human/mailbox verification; the runbook retains that owner gate.
