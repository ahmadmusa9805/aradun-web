## Implemented

- Strict source-shaped OutboxEvent, immutable event intent, schema/revision/timestamps and four declared indexes; automatic creation/indexing disabled. No TTL or retention policy invented.
- Transaction-required enqueue, deterministic dedupe without raw email in keys, conflicting intent rejection and rollback. No external operation inside a transaction.
- Atomic sorted claim, unique lease tokens, expiry/result fencing, sequential batches of at most five, bounded retries (five total attempts; 1/5/30/120-second backoff). Expired lease recovery also counts toward batch bounds. Stop-claim budget is 10 seconds, not a hard invocation deadline; eligibility and transport calls each have a 5-second timeout, lease 30 seconds. Database/network failures may extend elapsed time; no hosting SLA claimed.
- Permanent failure is terminal; eligibility failure never sends; revoked eligibility suppresses. Unknown transport acceptance/timeout and expired leases become uncertain; no automatic resend. Local reconciliation needs event ID, matching lease token and explicit synthetic disposition. This is test reconciliation, not proof of real provider acceptance.
- Backend-only authenticated POST `/internal/jobs/outbox/run`, credential verification before body/work, no-store, no input recipient/filter/template grants, 1KB JSON bound and per-router concurrent invocation refusal. Browser Origin requests denied; existing general CORS/origin policy retained. Missing secret denies access. Worker binding absent returns unavailable rather than pretending to run.
- Normal `OUTBOX_MODE=disabled`; no worker binding in ordinary server startup. Local-test requires test/development context, owned loopback marked disposable replica-set DB, explicit synthetic adapter and eligibility callback. No real network mail transport exists. SAMPLE reference and matching `.invalid` prospect recipient required. Staff recipient resolution must be supplied by trusted eligibility binding.
